# 항행경보 5단계: 검증된 구역의 지도 연결

로컬 구현이며 commit·push·배포하지 않았다. 새 라이브러리, 지도 엔진, 팝업, 수집 일정 또는 Pages 변경은 없다.

## 현재 실제 자료와 표시 제한

과거 수집 자료 9문서·94구역을 검사했다. **현재 표시 가능한 구역은 74개**다. 사용자 지시에 따라 앱 지도는 WGS84(EPSG:4326)를 기준으로 처리한다. 수집 원본의 측지계 메타데이터는 변경하지 않는다.

|검사 결과|구역 수|
|---|---:|
|지도 표시: 정상 DMS 및 명확한 경계 설명|74|
|정상 DMS 중심점에 반경이 있는 구역: Point로 축약하지 않음|18|
|잘못된 초 값 또는 지원하지 않는 도분 형식|2|

`26-392` 구역 1은 초가 67인 좌표가 있어 전체 구역을 제외한다. `26-402` 구역 1은 `36-47N, 125-20E` 도분 좌표이고 반경 구역이므로 지원하지 않는다. 원문은 그대로 상세에서 열람한다. 운영 public JSON은 미수집 상태를 유지하며 과거 자료로 덮어쓰지 않았다.

[공식 API 문서](https://www.data.go.kr/data/15057792/openapi.do)와 [제공기관 항행경보 상황판](https://www.khoa.go.kr/nwb/mainPage.do?lang=ko)이 출처다. 다른 항로표지·항공 자료의 WGS84 규칙을 이 API에 일반화하지 않는다.

## 간단한 검증 경계

`src/config/navigationalWarningMap.ts`에서 앱의 지도 좌표계를 설정한다. 지도 표시는 일반 DMS와 원문 설명이 명확한 구역만 지원한다.

`navigationalWarningMap.ts`는 일반적인 위도→경도 도분초만 재검사하고 수집기의 `coordinates.pairs`와 일치하는지 확인한다. 순서·분초·범위가 잘못되거나 부분 해석이면 전체 구역을 생략한다. Polygon은 원문의 ‘해당 지점을 순차 연결한 선내 해역’ 설명 및 자기교차·중복·면적 검사를 통과해야 하며 닫는 좌표만 마지막에 추가한다. 명시적으로 닫힌 경계의 마지막 반복 좌표는 검증 시에만 제거한다. Point는 단일 위치가 확인된 한 쌍만 허용한다. 반경 영역·선·미해석 형식은 지원하지 않는다.

## 기존 지도 코드 재사용

- 기존 행위허가처럼 GeoJSON FeatureCollection과 MapLayerConfig를 지도 퍼사드에 전달한다. 저장 키와 표시 레이어 ID는 `hazard` 그대로다. 같은 ID를 추가로 중복 등록하지 않는다.
- Leaflet의 기존 GeoJSON/`circleMarker`와 Kakao의 기존 Polygon/CustomOverlay 파싱·생성·cleanup을 사용한다. 행위허가의 기하 유효성 검사를 `validSimplePolygon`으로 공유하되 기존 허가의 4~20점·DMS 검사 조건은 그대로다.
- 경보는 장미색 `#e11d48`, 행위허가는 기존 노란색이다. 선택한 경보는 선 두께/점 반지름을 늘려 강조한다.
- 기존 카메라 bounds 이동 방식을 사용한다. 단일 위치는 한 점으로 이동한다. 지도 클릭은 기존 항행경보 패널에 해당 문서 상세를 열며 새 팝업을 만들지 않는다.
- 상세의 표시 가능한 구역에만 ‘지도에서 보기’를 제공한다. 누르면 레이어를 켜고 패널을 닫아 지도에서 확인한다. 원문·목록·뒤로가기 구조는 유지한다.
- 레이어 OFF 시 도형을 생성하지 않으며 기존 cleanup으로 제거한다. 경보 OFF 상태의 신규 접속은 JSON을 요청하지 않는다. ON 또는 패널을 열 때 기존 정적 로더를 사용하고 60초 메모리 캐시/동시 요청 합치기를 공유한다. 폴링하지 않는다.
- 원문 JSON은 기존 WarningData 하나를 공유하며, 지도 모델에는 식별자와 검증한 좌표만 둔다. `useMemo`로 데이터 변경 시만 변환한다. API 수집기·운영 JSON·Pages 워크플로·PWA 정책은 수정하지 않는다.

## 로컬 검증과 운영 전 확인

`npm test`, `npm run lint`, `npm run build`, `npm run verify` 및 `node scripts/verify-navigational-warning-preview.mjs`를 실행한다. 기존 로컬 Playwright/Chrome 설정 후 `node src/tests/navigationalWarningMap.browser.mjs`로 320·390·1280px, Leaflet/Kakao를 검사한다. 기본 테스트는 합성 자료를 브라우저 요청 인터셉트에만 사용한다. `QA_REAL_WARNINGS=1`이면 기존 개발용 fixture의 실제 9건·94구역으로 74개 폴리곤과 상세·지도 이동을 검증한다. 운영 JSON은 변경하지 않는다. Leaflet은 실제 라이브러리, Kakao SDK와 Firebase는 로컬 대역이다.

배포 전에는 실제 Kakao SDK, 지도 중심/확대, 원문과 도형의 일치, 모바일 터치를 운영 전 확인한다. 수집 범위와 취소·종료 규칙은 여전히 미확인이므로 현재 유효한 모든 경보라고 보장하지 않는다. 오래된 자료·실패·미수집 상태 안내와 개발용 미리보기의 운영 격리를 유지한다.
