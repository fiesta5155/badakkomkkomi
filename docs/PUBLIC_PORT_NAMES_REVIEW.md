두 CSV 원문은 공공데이터포털 다운로드로 확보했다. 파일 바이트는 EUC-KR 계열로 읽었다. 어촌어항관리시스템은 CSV 대신 공식 지도의 읽기 전용 POST 조회 응답을 저장했다. [원본 파일 및 SHA-256 목록](../data/sources/port-names/2026-11-20/manifest.json)에 조회 경로·매개변수·파일명을 기록했다. 원본 응답과 CSV는 로컬 보존본에 저장했다. 원본 CSV에는 위치와 무관한 등록 메타데이터도 포함돼 있어 정적 지도 데이터에는 좌표·지명 관련 필드만 사용했다.

지도 조회 화면이 LA/LO를 EPSG:4326 [경도, 위도]로 읽는 것을 확인했다. 지도 표시점을 동일 순서로 저장했다. 조회일은 2026-11-20이며 각 포인트의 기준연도는 제공되지 않아 null로 두었다. 사업연도와 조회일은 구분했다. 공식 어항 지도 표시점이 시설 중심점이나 개별 접안시설의 실측점인지 공개 응답에서 확인되지 않는다. CSV의 사업신청 항 및 행안부 선착장과 이름이 같아도 시설 단위를 확인하기 전에는 병합하지 않는다.

관리 해역 우선 범위는 통영·거제 행정구역으로 정했다. 주소와 시군코드가 함께 일치하고 좌표가 지역 검수 범위(위도 34.5–35.15, 경도 128–128.85) 안에 있는 행을 담았다. 이 범위는 명백한 수치 오류를 걸러내는 검사다. 후보 166곳의 ID, 동일 명칭·주소 조합, 좌표쌍이 각각 유일하다. 통영 수월항처럼 같은 이름이라도 주소가 다른 시설은 유지했다. 해안선 이동, 좌표 합성, 항로 접근점 또는 미확인 기존 좌표 입력은 하지 않았다.

## 기존 목록의 미확인 항·포구

- **확보 자료에 일치 명칭 없음** 통영항, 세포항, 도산 저산항, 원평항, 창좌항, 비진항, 사량 백학항, 매물도 당금항, 소매물도항, 만지항, 장승포항, 옥포항, 고현항, 근포항, 대포항, 홍포항, 가조도 창호항, 둔덕 시목항, 거제 외간항, 외도선착장, 수양항, 아주항
- **사업신청 자료에 명칭 있음, 사용 가능한 좌표 없음** 달아항, 가오치항, 사량 진촌항, 욕지 도동항, 욕지 유동항, 욕지 노대항, 우도항, 매물도 대항, 추도 대항
- **동명 위치 또는 명칭 대응 확인 필요** 삼덕항, 궁항, 죽림항, 용남 화삼항, 한산 제승당항, 진두항, 좌이도선착장, 해금강항, 구영항

좌이도선착장은 동좌항·서좌항 중 어느 곳인지 미확정이다. 후보에는 공식 ID가 다른 두 항구가 각자 기록돼 있다. 만지항은 확보한 세 자료에서 위치를 확인하지 못했다. 주소와 시군코드가 충돌한 동호항 1행, 양화항 2행, 여차항 2행, 송포항 1행, 옥동항 2행은 비교 JSON에 원문 값으로 보존했다.

## 검토 실행과 운영 교체

- [최초 후보 166곳 GeoJSON](../data/public-port-names.candidate.geojson)은 검토 원본으로 보존한다. 일반 개발 모드와 로컬 운영 빌드는 승인된 154곳을 사용한다.
- 우선 어의항, 사량 대항, 칠천도 송포항 등 1km 이상 차이가 나는 곳과 주소·코드 불일치 행을 공식 상세 지도 또는 담당기관 자료로 대조한다. 누락된 시설은 공식 좌표 또는 대상이 확인된 사용자 GPS가 확보되면 출처·기준일과 함께 별도 추가를 제안한다.
- 교체 승인 시 명칭 레이어의 데이터 연결만 전환한다. 후보에 없는 40개 기존 명칭의 유지 또는 제외와 후보 전수 적용 범위를 승인 내용에 명시한다. 경로 및 접안 자료는 별도로 유지한다.
- `node scripts/build-public-port-names.mjs`로 보존된 원본에서 후보와 비교 JSON을 재생성한다. 웹 호출 없이 동작하고 원본 파일 해시를 검사한다.
- 이전 로컬 변경 파일과 원본 81곳, Git 좌표 이력은 작업 전 `.dev/backups/port-dataset-rebuild-2026-11-20-055701/`에 보존했다. [기존 좌표 검수 및 GPS 절차](./PLACE_NAME_COORDINATES.md).

## 2026-11-20 지도 위치 검증

후보 전수에 대해 어촌어항관리시스템 원본의 ID·명칭·주소·좌표를 다시 대조했다. 166곳 모두 원본 값과 일치했다. 그다음 166곳과 기존에 제외한 8행의 공식점 주변 약 475m 폭 위성영상을 각각 확인했다. 영상에서 방파제·물양장·잔교 등 실제 시설과 그 배후지를 식별하고, 어항의 이름과 지역은 공식 구역도·현황·섬 경계 자료와 대조했다. 각 행의 영상과 자료 링크는 [전수 검증 원장](./data/public-port-names-location-verification.json)에 기록했다. 영상 번호는 원장의 contactSheet 및 frame에 대응한다.

| 후보 166곳 판정 | 건수 |
|---|---:|
| 일치 확인 | 83 |
| 위치 불일치 의심 | 2 |
| 명칭·중복 확인 필요 | 10 |
| 검증 보류 | 71 |

일치 확인은 지명·지역 자료와 영상의 항만 시설 배치가 함께 맞는 경우에 부여했다. 지명 자료가 충분하지 않으면 영상에 시설이 있더라도 보류했다. 개별 접안점의 측량 정확도나 항계 내부 여부까지 확인한 결과는 아니다. 영상에는 지명이 표시되지 않고 촬영일은 위치별로 다를 수 있다. 카카오맵 링크는 후속 대조용이며 전수 판정은 카카오 검색 결과가 아니라 실제로 열어 본 위성영상과 명칭을 대조한 문서에 근거한다. 공개 OSM 원격 조회는 제한 응답 등으로 전수 자료를 얻지 못해, 저장소 OSM 해안선과 WFS 섬 경계를 선별에 활용했다. 섬 경계의 최근접값은 해당 섬에 속한다는 뜻이 아니며, 범위 밖 좌표에 대해서는 해안선 거리를 지리적 근거로 쓰지 않았다.

후보 집합에서 공식 ID, 이름·주소 조합, 좌표쌍 중복은 없었다. 근접한 계도항·군령포항(약 197m), 진두항·창외항(약 209m)은 영상의 시설 위치와 별도 명칭을 대조했다. 동명이거나 인접하다는 이유로 병합하지 않았다. 다른 이름으로 등록된 동일 시설까지 모두 배제할 수는 없다.

`node scripts/build-port-names-final-candidate.mjs`로 최종 후보를 재생성하고 `--check`로 저장본을 검증할 수 있다. 생성 단계는 166개 판정과 원본의 항명·주소·좌표·시군 코드·출처를 대조하며 중복 ID·좌표쌍·동일 명칭과 주소의 중복을 검사한다. 동일 이름과 다른 주소의 수월항은 검증 원장의 별개 항목이다.

브라우저 회귀 검사에서 일반 개발 81곳과 후보 모드 154곳을 각각 320·390·1280px에서 확인했다. 실제 Leaflet과 합성 Kakao SDK에서 이름과 좌표가 전수 일치했고, 줌 10·11·12·14·16·11의 심볼 유지, 표본 4곳의 이름표 끝과 심볼 정렬, 레이어 ON/OFF, 경로와 다른 레이어 데이터 유지가 통과했다. 실제 Kakao SDK는 로컬에서 `DOMAIN_MISMATCH_OR_BLOCKED`로 연결이 되지 않아 Leaflet으로 전환됐다. 운영 적용 전 Kakao 연결이 가능한 테스트 환경에서 실제 지도를 확인해야 한다. `npm test` 157개, build, verify가 통과했고 lint는 기존 경고 12건만 남았다.

### 최종 승인과 운영 적용

사용자가 공식 좌표 154곳의 지도 위치를 직접 확인하고 운영 반영을 승인했다. 바다수첩의 항·포구 명칭 레이어는 [승인 스냅샷](../data/public-port-names.final-candidate.geojson)을 사용한다. 검증 보류 71곳의 판정과 출처를 유지한다. 제외 12곳, 주소·코드 불일치 8행 및 공식 자료와 대응하지 않은 기존 40곳은 운영 명칭 레이어에서 제외한다.

[지도 데이터 변환](../src/data/portNameMapPoints.ts)은 공식 GeoJSON의 경도·위도를 두 지도 엔진에 그대로 전달한다. 이름표와 심볼은 같은 기준점을 사용한다. 명칭 레이어의 표시 설정은 기존 접안·위험정보·보호구역과 독립적이다. [전환 전 81곳의 원본과 명칭 좌표 이력](./PLACE_NAME_COORDINATES.md)을 보존한다.
