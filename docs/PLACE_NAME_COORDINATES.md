# 항·포구 및 섬 지명 좌표 유지보수

공공자료 기반 후보와 기존 목록의 비교는 [데이터셋 재구축 검토](./PUBLIC_PORT_NAMES_REVIEW.md)에 기록한다. 현재 운영 명칭은 [154곳 스냅샷](../data/public-port-names.final-candidate.geojson)을 사용한다. 좌표 변경은 공식 ID 기준으로 근거와 새 검증 상태를 기록한 뒤 승인받고, 운영 스냅샷과 검증 절차를 함께 갱신한다. 아래 81곳 자료와 정정 절차는 전환 전 이력으로 보존한다.

기준일: 2026-11-20. WGS84(EPSG:4326) 십진수 위도·경도를 사용한다. 사용자 제공 GPS를 우선적인 수정 근거로 삼으며, 개발자가 데이터를 수정한다. 일반 사용자 좌표 편집기·검수 화면은 추가하지 않는다.

## 전환 전 81곳의 데이터와 표시 이력

- [ports.json](../public/data/ports.json)의 136개 원본 항구·접안 기록과 300개 변침점은 보존 사전이다. 전환 전 목록은 category=port 81개 ID·이름이었다. seaApproach·항로 서비스와 연결하지 않는다.
- [portNameLocations.ts](../src/data/portNameLocations.ts)가 승인된 명칭 전용 정정 원장이다. 최신 승인 기록과 기록이 없는 ID의 보존 사전 lat/lng가 각각 전환 전 표시 좌표를 결정했다. 지도 클릭·경로 선택에는 정정 원장을 사용하지 않는다.
- [81곳 검수 원장](./data/port-name-coordinate-audit.json)에 보존 좌표·표시 좌표·검증 상태·Git 좌표 변경 이력을 별도로 기록한다. [공식 응답 근거](./data/port-name-source-evidence.json)를 함께 보존한다.

## 섬 명칭 및 좌이도 조사

사용자가 문제 표식을 항·포구 명칭의 **좌이도선착장(KR-GN-TY-0040)**으로 확인했다. 기본 설정에는 독립 섬 지명 레이어가 없으며, 전환 전 표식은 ports.json의 lat/lng에서 나왔다. 최초 42d7672부터 34.772000,128.442000이고 접근점은 별도의 34.779000,128.443500이다. 어느 값을 표시하는지 두 지도에서 대조하며 접근점을 쓰지 않는다.

[islands_tongyeong_geoje.geojson](../public/data/islands_tongyeong_geoje.geojson)의 WFS islnds_nm=좌도(48220:0042) 경계 범위는 경도 128.494598–128.510711, 위도 34.787380–34.804071이다. 기존 표식은 이 경계 밖에 있다. 이 파일은 경로 요약에 쓰는 폴리곤이고 지도 명칭 기준점 파일이 아니다. 섬 중심/바운딩박스 중심으로 좌표를 임의 이동시키지 않는다. 폴리곤과 OSM 지도 대조는 오류 검토 근거이며 선착장 대상 식별을 대체하지 않는다.

해양수산부 공개 지도 조회에서 확인된 후보는 다음과 같다. 기존 좌이도선착장이 어느 항구인지 미확정이므로 **둘 다 미적용**이다. 사용자 GPS 또는 대상 식별과 좌표 승인을 받아야 한다. 지명 자체도 임의로 좌도로 바꾸지 않는다.

| 검토 대상 | 현재 명칭 좌표 | 가능한 항구 후보 (위도, 경도) | 출처·검증 상태 |
|---|---|---|---|
| 좌이도선착장 → 동좌항 여부 확인 필요 | 34.772000,128.442000 | 34.800396, 128.507884 | FP002255, 경상남도 통영시 한산면 창좌리 1-3; 항구 자료 확인, 기존 ID와 동일 대상인지 미확정·승인 대기 |
| 좌이도선착장 → 서좌항 여부 확인 필요 | 34.772000,128.442000 | 34.794852, 128.496763 | FP002256, 경상남도 통영시 한산면 창좌리 340-5; 항구 자료 확인, 기존 ID와 동일 대상인지 미확정·승인 대기 |

배경지도 자체의 섬 글자·심볼 배치는 Kakao/OSM 공급자가 관리한다. 앱의 명칭 마커 문제와 구분한다. 다른 지역의 기본 지도 표식을 이번 수정으로 제어한다고 주장하지 않는다.

## 좌표 오류와 렌더링 오류의 구분

원형 심볼 중심과 이름표 삼각 끝은 52px 요소의 (26,26)에 고정한다. 이름표 본체 하단 y=20, 6px 삼각 끝 y=26, 심볼 중심 y=26이며 연결부가 겹쳐 보이므로 분리된 점과 글자처럼 보이지 않는다. 원형 심볼은 이름표 유무와 관계없이 유지해 확대 시 심볼만 사라지지 않게 했다. 지리 좌표에 픽셀 오프셋을 합산하지 않는다. Leaflet iconAnchor=(26,26), Kakao xAnchor=yAnchor=0.5다.

줌 12 미만은 심볼만 표시하고, 12 이상은 120×36px 충돌 배제로 이름표를 선별하는 기존 정책을 유지한다. 이름표는 padding 포함 최대 120px다. 점 선택 시 확대 수준과 무관하게 이름을 확인할 수 있다. 선택된 이름표가 기존 라벨과 잠시 겹치는 동작은 유지한다. 명칭 ON/OFF도 기존 설정을 사용한다.

좌이도 표식의 **심볼 소실은 렌더링 문제로 수정**했다. **해상 위치는 저장 좌표 문제로 남겨 승인 대기**한다. CSS 보정으로 수 km 좌표 오류를 감추지 않는다.

## 전환 전 81곳의 GPS 반영 절차 (보존)

1. 사용자가 제공한 지점명·좌표·측정일·기기/정확도(알 수 있으면)와 출처를 기록하고, 같은 이름의 여러 포구 중 어느 곳인지 ID로 확인한다. WGS84 십진수 위도·경도인지 확인한다. GPS 근거를 웹 지오코딩이나 과거 해상 회피점보다 우선 검토한다.
2. 확인되지 않은 수치나 대상은 적용하지 않고 검수 원장의 review-required로 유지한다. 항구 이름으로 검색한 근사 좌표나 섬 중심을 추정해 넣지 않는다.
3. 사용자 승인된 좌표는 portNameLocations.ts의 PORT_NAME_LOCATION_CORRECTIONS **맨 뒤에 새 기록을 추가**한다. portId/name, previous(현재 명칭 좌표), position(새 GPS), source.kind=user-gps, source.reference/detail(제공 근거), approvedOn을 기록한다. 공개 문서에 불필요한 개인정보는 적지 않는다. 기존 기록을 덮어쓰지 않으며 동일 ID의 마지막 승인 기록이 적용된다.
4. docs/data/port-name-coordinate-audit.json의 displayPosition·상태·근거를 갱신하고 좌표 이력을 추가한다. Git 이력과 기존 기록을 보존한다. GPS 기록을 넣기 위해 ports.json의 lat/lng·seaApproach 또는 docking_points.geojson을 수정하지 않는다.
5. 명칭 전용 단위/브라우저 검사의 예상값을 새 승인 좌표에 맞추고 원본 데이터가 변하지 않았는지 확인한다. npm test, npm run lint, npm run build, npm run verify를 실행한다. 확대·축소, 이름표/심볼 앵커, ON/OFF, 경로·다른 레이어를 검증한다.
